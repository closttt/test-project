### A1. Библиотека знаний (третья вкладка «Библиотека» в /knowledge)

Сущность `LibraryItem` (Supabase `library_items`, тот же single-user RLS, что у ссылок):

| поле | смысл |
|---|---|
| `type` | book / article / video / podcast / course / tool / other — иконка + цвет |
| `title`, `author`, `url`, `domain` | url необязателен (книга может быть без ссылки) |
| `coverUrl` | загрузка в bucket `library-covers` или og:image из ссылки |
| `description` | короткое «о чём» |
| `notes` | markdown-заметки (рендер через `lib/markdown.tsx`) |
| `tags[]` | общие с остальным приложением (`lib/tags.ts`) |
| `status` | want / doing / done — «Хочу / В процессе / Готово» |
| `favorite`, `rating` (1–5) | избранное + оценка |
| `sourceCardId` | если создано из телеграм-поста |

Экран:
- Шапка: счётчик элементов (как «2437» в ролике), поиск, кнопка «Добавить».
- Фильтры-чипы: тип, статус, избранное, теги. Сортировка: новые / старые / А-Я / оценка.
- Сетка карточек с обложкой (fallback — цветная плашка с иконкой типа, как у ссылок) / список.
- Добавление: вставил ссылку → `api/unfurl.ts` тянет og:title/og:image/description,
  тип определяется по домену (youtube → video, spotify/apple podcasts → podcast, …), можно
  поправить руками. Без ссылки — ручная форма + загрузка обложки.
- Карточка элемента: боковая панель (Sheet) — обложка, поля, заметки с автосохранением,
  «В избранное», статус, «Открыть источник», удалить с undo.
- Мост из «Постов»: кнопка «→ в Библиотеку» на телеграм-карточке.
- Инструмент ассистента `save_to_library(url|title, type?, notes?)` — одна запись в
  `AI_TOOLS`, добавляется в конце потока A, когда B уже влил свои инструменты.

Не делаем (не Obsidian): wiki-ссылки между заметками, граф, папки, бэклинки, локальные md.

### B0. Вход в приложение (обязательно до Gmail)

Сейчас любой, у кого есть URL, видит всё. Перед подключением почты — простой пароль:
`APP_PASSWORD` в env Vercel → `api/auth/login.ts` ставит подписанную httpOnly-cookie
(`APP_SECRET`) → все `api/gmail/*`, `api/notion/*` проверяют её. Экран входа один раз на
устройство. Supabase-данные остаются как есть (single-user, уже принятый компромисс).

### B1. Gmail внутри CRM (страница «Почта»)

Серверная часть (Vercel functions):
- `api/google/auth.ts`, `api/google/callback.ts` — OAuth 2.0, refresh-токен в Supabase
  таблице `integration_tokens` (доступ только через `SUPABASE_SERVICE_ROLE_KEY` с сервера).
- `api/gmail/threads.ts` (list/search по label), `api/gmail/thread.ts` (одна цепочка,
  тела писем), `api/gmail/modify.ts` (прочитано / звезда / архив), `api/gmail/send.ts`
  (ответ) — последнее опционально, см. вопросы.

UI `src/pages/Mail.tsx` в стиле приложения:
- Список: Входящие / Со звездой / Отправленные + поиск Gmail-синтаксисом.
- Цепочка: письма аккордеоном, HTML в sandboxed `<iframe>` (санитайз, картинки по клику),
  вложения — ссылками.
- Действия: прочитано, звезда, в архив, ответить; **«→ Задача»** (создаёт Task с ссылкой
  на письмо в `links`), **«→ Встреча»** (если в письме .ics/ссылка на созвон — предзаполнить
  Meeting). Автосоздание встреч — позже, сначала ручная кнопка.
- Бейдж непрочитанных в сайдбаре, обновление по фокусу вкладки (как у «Постов»).

Ограничение Google: scope `gmail.readonly`/`gmail.modify` — restricted. Варианты:
- аккаунт `abondar@axevil.com` в Google Workspace → OAuth-приложение типа **Internal**:
  без верификации, токены не протухают. Лучший путь.
- обычный gmail.com → режим Testing (refresh-токен живёт 7 дней, надо перелогиниваться)
  либо проходить верификацию. Хуже.

### B2. Notion через ассистента (без своего UI Notion)

- Internal Integration Token (не OAuth) → `NOTION_TOKEN` в env, прокси `api/notion.ts`.
- В настройках: выбрать целевую страницу/базу по умолчанию («Инбокс»).
- Инструменты ассистента: `notion_create_page(title, markdown, parent?)`,
  `notion_append(page_query, markdown)`, `notion_search(query)`.
- Кнопка «→ в Notion» на заметке и (позже) на элементе Библиотеки.
- Уточнение по «MCP»: наш веб-ассистент не может подключиться к MCP-серверу Claude Code;
  делаем то же, что делает Notion MCP внутри — вызываем Notion REST API. Для пользователя
  разницы нет: «закинь это в Notion» работает из чата.

### B3. Ассистент как оператор экосистемы

- Инструменты Gmail: `search_mail(query)`, `read_thread(id)` → «что мне писали по X»,
  «сделай задачу из письма от Y».
- Контекст (`aiContext.ts`): непрочитанных писем, ближайшие встречи, задачи на сегодня.
- Инструменты выполняются на клиенте, но ходят в наши `/api/*` с cookie из B0.
- Каждый инструмент-мутация — через `pushUndo`, как сейчас.

Порядок: B0 → B2 (простое, сразу виден результат) → B1 → B3.

## Идеи сверх задания (на решение)

1. **Утренний брифинг** на дашборде (как «Брифинг дня» в ролике): ассистент раз в день
   собирает почту за ночь + встречи + задачи в одну карточку. Легко после B3.
2. **Share Target** в `manifest.webmanifest`: «Поделиться» с телефона → ссылка сразу в
   Библиотеку. Дешёво, сильно упрощает захват.
3. **Глобальный поиск** через существующую командную палитру (cmdk): задачи, заметки,
   библиотека, письма — один хоткей.
4. **«Прочитать сегодня»**: виджет на дашборде подсовывает один элемент из статуса «Хочу».
5. **Google Calendar** тем же OAuth: встречи из календаря напрямую в CRM (сейчас через
   Hermes-инбокс). Один дополнительный scope.
6. **Спросить у базы** (RAG по Библиотеке через pgvector) — позже, когда наберётся контент.
