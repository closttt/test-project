# Настройка: Supabase и переменные после деплоя

Порядок: сначала SQL в Supabase, потом переменные в Vercel, потом редеплой. Всё, что здесь
описано, делается один раз.

---

## 1. SQL в Supabase

Где: [supabase.com](https://supabase.com) → ваш проект → левое меню **SQL Editor** →
**New query** → вставить весь файл целиком → **Run** (или Ctrl+Enter).

Все файлы идемпотентные: повторный запуск ничего не сломает и не выдаст ошибку «уже существует».

| Файл | Зачем | Нужен |
|---|---|---|
| `supabase/library_items.sql` | «Библиотека» + бакет для обложек | да, прямо сейчас |
| `supabase/integrations.sql` | хранилище refresh-токена Google | да, если подключаете Gmail |
| `supabase/app_state.sql` | синк задач/проектов между устройствами | уже выполнен |
| `supabase/knowledge_cards.sql` | карточки из Telegram | уже выполнен |
| `supabase/knowledge_links.sql` | полка ссылок | уже выполнен |
| `supabase/incoming_meetings.sql` | инбокс встреч от Hermes | по желанию |
| `supabase/push.sql` | пуш-напоминания при закрытой вкладке | по желанию |

Как проверить, что получилось:

- **Table Editor** → в списке появились `library_items` и `integration_tokens`.
- **Storage** → появился публичный бакет `library-covers`.
- В приложении на вкладке «Библиотека» пропала жёлтая плашка «Таблица ещё не создана».

Если плашка осталась, обновите страницу: статус проверяется один раз при загрузке.

## 2. Переменные в Vercel после деплоя

Где: [vercel.com](https://vercel.com) → проект → **Settings** → **Environment Variables** →
добавлять по одной, окружение **Production** (и **Preview**, если пользуетесь превью-ссылками).

### Уже должны быть (фронтенд)

| Переменная | Значение |
|---|---|
| `VITE_SUPABASE_URL` | Supabase → Settings → API → Project URL |
| `VITE_SUPABASE_ANON_KEY` | там же, ключ **anon / publishable** |

### Новые, серверные. Префикса `VITE_` быть не должно

Всё, что ниже, читают только функции в `api/`. С префиксом `VITE_` ключ попадёт в браузерный
бандл, то есть станет публичным. Это особенно критично для service-role ключа.

| Переменная | Откуда брать | Обязательна |
|---|---|---|
| `SUPABASE_URL` | тот же Project URL, что и в `VITE_SUPABASE_URL` | для Gmail |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Settings → API → **service_role**, секретный | для Gmail |
| `GOOGLE_CLIENT_ID` | Google Cloud, см. раздел 3 | для Gmail |
| `GOOGLE_CLIENT_SECRET` | Google Cloud, см. раздел 3 | для Gmail |
| `NOTION_TOKEN` | Notion, см. раздел 4 | для Notion |
| `APP_PASSWORD` | придумываете сами | по желанию |
| `APP_SECRET` | любая длинная случайная строка | по желанию |
| `APP_URL` | `https://ваш-домен` | только если редирект уходит не туда |

Про пароль: если `APP_PASSWORD` пустой или не задан, вход выключен и сайт открыт всем, у кого
есть ссылка. Как только вы подключаете почту, пароль стоит задать. `APP_SECRET` необязателен,
без него подпись куки берётся из пароля. Смена любого из них разлогинивает все устройства.

**После добавления переменных обязателен редеплой.** Vercel не применяет их к уже собранному
деплою: Deployments → последний → «…» → **Redeploy**.

## 3. Google для Gmail

1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект или выбрать свой.
2. **APIs & Services** → **Library** → найти **Gmail API** → **Enable**.
3. **OAuth consent screen**: раз `abondar@axevil.com` в Google Workspace, выбирайте тип
   **Internal**. Это снимает проверку приложения Google и делает refresh-токены бессрочными.
   На External токены живут 7 дней в тестовом режиме, и придётся перелогиниваться каждую неделю.
4. **Credentials** → **Create credentials** → **OAuth client ID** → тип **Web application**.
5. В **Authorised redirect URIs** добавить точно, со схемой и без слеша в конце:
   ```
   https://ваш-домен/api/google/callback
   ```
   Если пользуетесь `vercel dev` локально, вторым пунктом добавьте
   `http://localhost:3000/api/google/callback`.
6. Скопировать **Client ID** и **Client secret** в переменные Vercel из раздела 2.
7. Редеплой, затем в приложении: **Сервисы** → плитка **Gmail** → **Подключить** → выбрать
   аккаунт → разрешить доступ. После возврата статус станет «Подключено».

Запрашивается один доступ, `gmail.modify`: читать письма, помечать прочитанным, ставить звезду,
архивировать. Отправка писем не запрашивается и не реализована.

## 4. Notion

1. [notion.so/profile/integrations](https://www.notion.so/profile/integrations) → **New
   integration** → тип **Internal** → скопировать **Internal Integration Secret**.
2. Положить его в `NOTION_TOKEN` в Vercel, редеплой.
3. Самое частое место, где всё встаёт: **дать интеграции доступ к страницам**. В Notion откройте
   нужную страницу или базу → меню «**…**» справа сверху → **Connections** → выберите свою
   интеграцию. Без этого шага поиск возвращает пустоту, и выглядит это как «ничего не работает».
4. В приложении: **Сервисы** → плитка **Notion** → в списке отметьте звёздочкой страницу по
   умолчанию. Именно в неё ассистент будет складывать то, что вы просите в чате.

## 5. Проверка, что всё живо

- **Библиотека**: /knowledge → вкладка «Библиотека» → нет жёлтой плашки, добавляется элемент,
  кнопка «Заполнить» подтягивает название и обложку по ссылке.
- **Сервисы**: /services → у Gmail и Notion зелёные точки и подписи «Подключено».
- **Почта**: письма грузятся, из письма делается задача.
- **Ассистент**: попросить «закинь в Notion заметку про X» и проверить, что страница появилась.

Если что-то из этого не работает, смотрите Vercel → Deployments → последний → **Functions**:
функции отдают человекочитаемую причину, например «GOOGLE_CLIENT_ID не задан».
